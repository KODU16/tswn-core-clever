# 会员制餐厅

挑战字符串为 `会员制餐厅@!`，图标 🍽️。外显 HP114、攻11、防45、速14、敏19、魔19、抗8、智10；实际速度106。餐厅可被选中，免疫伤害和正负状态，正常行动固定交替烹饪、喂菜，不执行普通攻击。

从其他角色真正发动的技能日志及敌方人物抽取2～3项食材，人物被烹饪移除，始终保留至少一个非召唤本体。菜名按“食材—随机方法—食材”连接，三项使用两个方法；122种方法的读音和说明可悬停查看。喂菜只选择敌方本体，分身属于本体，召唤物不参加食客抽选。

日志材料可包含任意已接入引擎执行入口的原版、武器和专属技能，不按35项白名单过滤。餐厅自身和喂菜派生技能不再回收。真正的普通攻击也能抓为“普攻”食材，由虚拟厨师按普通物理攻击结算。技能保留真实施法来源、调用参数和发动上下文；原角色死亡或被烹饪也可结算，原函数修改会直接影响菜品。

只剩一个敌方本体且没有可用技能日志时，随机挑选两种不同的原版35技能，由不入场的虚拟角色（HP300、外显全属性90）施放。菜名没有任何技能时也由该虚拟角色随机施放1～5种原版技能。无对敌动作的原版自身增益与被动按确认规则给予食客。虚拟厨师只存在于内部结算，不出现在角色列表、属性栏或可见回放中，喂菜日志只显示食客受到的伤害、状态等效果，不显示餐厅或原施法者的攻击与技能发动提示。烹饪只保留“开始烹饪，做出……”一句，不另报“端出”。

左侧边栏菜名完整换行显示，包括死亡后的菜品。菜品 HP100，被击倒且尚未喂出时不产生效果、不计入已喂数量，餐厅下次行动重新烹饪。完整烹饪—喂菜额度为初始敌方本体人数×10，每成功分身增加10。完成额度后若仍有敌人存活，发动尖锐爆鸣击倒自身。每场重新计算额度；回放、快照与胜率续局保存同一配方和技能上下文。

## 技能维护

机制文件的 CombatRuntime impl 使用 `#[tswn_skill_capture::capture_skills(模块名)]`。宏自动捕获可序列化的执行参数并生成同源重放函数，修改原技能函数不需要另写餐厅版效果。内层具体招式优先于外层随机选招器；调用凭据不根据显示名称查找函数。新增同一模块内的标准技能入口自动参与捕获；新机制模块需接入相同宏及统一重放分发。

标准“使用／发动／施放”等日志自动提取任意名称。没有标准发动文案的技能用 RunUpdate::with_skill_name 显式标明语义名称（如观察、648）；这是日志元数据，不是餐厅技能名单。值参数通过 serde 通用保存，包含枚举、数组和可序列化结构体；新的参数类型需支持 serde，实体与目标列表在重放时统一替换为食客。菜品重放通过目标覆盖锁定食客，技能本身的伤害、免疫、状态和死亡链仍调用当前引擎实现。
